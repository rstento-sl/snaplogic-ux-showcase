Services catalog

API Manager > Manage > Services Catalog

Work in progress

Services catalog and navigation pane

When a customer selects API Management from the waffle menu, the Services catalog opens. The Services catalog page and left navigation pane should be intuitive to both Classic APIM and new APIM 3.0 customers from the first encounter throughout their experience. Where it is impossible to be intuitive, in-app assistance can help them self-serve to onboard quickly and successfully use APIM 3.0.

The first experience

Everyone meets this page on day one:

  • Classic APIM customers adding APIM 3.0
  • Customers new to APIM
  • The first person to create a service, and all who follow

The page doesn't introduce itself

The heading reads Catalog Stats, which names the first widget on the page, not the page. Nothing defines a service, says what the catalog does, or separates it from the Policy catalog sitting beside it in the navigation pane. Refer to pin 1 →

Blank page

In two cases, the rest of the page is blank: if no services have been created, or if services have been created but the current customer doesn't have read permission to view them.

Ambiguous action button

The Add service button has a hidden option, available from the caret: adding from a specification. Nothing explains what a service is, or what the difference is between the two ways to add one.

Existing Classic APIM customers

Nothing connects APIM 3.0 to the product they already know

They arrive fluent in Proxies, API versions, and subscriptions, and the page says service. No page maps the old vocabulary to the new, so they can't tell whether what they're looking at is empty or simply unfamiliar.

The navigation points them back at the old product

API Manager names two things: the product itself, and an item under Classic API Management. The Classic one is the name they recognize, so the familiar click leads out of the product they're evaluating. Their real first task is migration, but Migration Tool sits below Manage, under a section heading over a single link that never says what migrates to what. Nothing says whether Classic is deprecated, whether both run side by side, or whether migrating affects live traffic. The nav is its own comparison, since these problems follow a customer onto every APIM page: the left navigation pane.

After services exist

Ambiguous folder rows

Each row shows a folder icon and a name, so you must open folders one at a time to find anything. The name is a path, <Project space>/<Project>, but both levels carry the same icon, and the root shared folder shows no prefix at all. Nothing tells you how many services a folder holds, which ones are yours, or that every listed folder holds at least one.

The statistics count the wrong unit, and define nothing

Publishing applies to a service version, not to a service, so one service can sit in several buckets at once. The five counts also mix publication with lifecycle, and nothing explains how Private differs from Restricted — where most people guess wrong, because Private is the status that isn't in the Developer Portal. The totals describe the whole environment, which tells a user nothing about their own work. Refer to pin 2 →

Filters appear inactive

The text and box colors resemble a disabled control, which discourages users from trying the filters. Filter by project is only useful if you already know which project a service is in; Filter by tags and Filter by owners are the most useful, but there's no way to find a service by name. The only sign that a filter is active is a purple circle holding the number of selections. The filters don't follow the design of the filters in Admin Manager or Monitor, which are much more refined.

It won't hold up at customer scale

Opening folders is the only way through the list, and a test environment already holds 32 services across 71 versions. The page does have a search box — it finds services by name and opens the folders that match — but it renders invisible, so nobody reaches it. That's a one-line defect, not a missing feature: the hidden search box. Even with it back, folders stay the wrong default. The data behind the page already names the project each service belongs to, so the list could open with services at the top level, each showing its path — one list to scan, sort, and search, instead of a folder tree to guess at. The list respects permissions; whether the statistics do is unconfirmed, and if they don't, the counts describe an environment the viewer can't see.
