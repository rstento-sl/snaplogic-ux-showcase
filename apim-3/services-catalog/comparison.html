In-app help idea: Onboarding

This page is the first thing a user sees in API Management, and it explains nothing about what a service is or what to do first. A dismissible onboarding flow could orient a newcomer without adding permanent page copy — offered, not forced: “New to API Management? Take a 2-minute tour,” with Start tour and Not now.
Proposed steps
  1. What this page is — the Services catalog lists every service in your environment, grouped by the project folder it lives in. Expand a folder to see the services inside it.
  2. What a service is — one API you manage in APIM 3.0: its versions, its policies, and who can call it.
  3. What the counts mean — the row at the top totals your service versions by status, so you can see how many are still unpublished.
  4. How to add one — Add service creates a service from scratch; the caret beside it adds one from an existing API specification.
  5. Watch the 90-second tour — a short video covering the same ground, for anyone who'd rather be shown than read.
Keep it recoverable: someone who clicks “Not now” on day one still needs it on day three, so the tour must stay reachable afterward — through the page's Learn more link or a help entry in the header.
